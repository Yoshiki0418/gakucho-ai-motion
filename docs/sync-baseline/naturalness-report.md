# 自然さ改善レポート（①タグ位置 / ②自動補完 / ③音声駆動）

- 実施日: 2026-08-26
- 目的: 「タイミングは合ったが、その瞬間の行動と発話が自然か」への対応
- 主指標: **無動作率** = 喋っているのに体が動いていない時間の割合

## 結果

| 段階 | 無動作率 | モーション数 | 担当発話からのズレ(中央値) |
| --- | --- | --- | --- |
| 改修前 | 87.8% | 5 | −111 ms |
| フェーズ0（時間同期） | 87.8%※ | 5 | +76 ms |
| フェーズ1（タグ導入） | 84.7%※ | 6 | +135 ms |
| **①+②（配置改善＋自動補完）** | **43.3%** | **16** | +3184 ms |
| **③ SentiAvatar（音声駆動）** | **12.6%** | 15 | **+28 ms** |

※ 改修前〜フェーズ1 の無動作率はモーション尺 2.57 秒の近似値。
①②以降は実測の再生尺（`[SYNC] motion_playing`）から算出しており、
**①②と③のみが厳密に同条件の比較**。

## 各施策の内容と効果

### ① タグ位置の改善

**問題**: 全タグが ratio 0.00（文頭）に固まっていた。
前回「句点の直前に置くな」と指示した結果、逆に文頭へ全振りになっていた。

**対応**: ○×の対例を 5 つに増やし、「動作が指し示す語の直前」と明示。
文頭・文末どちらもダメだと両方示した。

**効果**: 位置が文中（0.4〜0.5）に分散。ただし**単独では無動作率をほとんど動かさない**
（位置が直るだけで動作の量は増えないため）。

### ② 長文への自動補完

**問題**: 11 秒・13 秒の文が丸ごと無動作。タグ方式は「LLM が書いてくれること」に依存する。

**対応**: 発話長を文字数から見積もり（日本語 TTS 実測 約6文字/秒）、
**3.5 秒につき 1 つ**を目安に不足分を機械的に補う。
中立的な動作（うなずき→指し示す→どうぞ→考える）を順に回して反復感を避ける。
既存タグの近く（±0.18）は避ける。

**効果**: **無動作率 84.7% → 43.3%、モーション 6回 → 16回。**
LLM の遵守に依存しないため、これが実質の底上げになっている。

途中で `claim_prompt` の重複抑止が**応答全体**で効いており、
別々の文での自然な繰り返し（長い応答で 2 回うなずく等）まで潰していた。
**発話単位**の抑止に変更した。

### ③ SentiAvatar（音声駆動）の本番接続

**実装したもの**
- **常駐推論サーバ**（`/opt/sentiavatar-eval/sentiavatar_server.py`）
  公式スクリプトは毎回モデルをロードし直すため 1 本数秒かかる。
  HuBERT / Mask Transformer / RVQVAE を常駐させ、**レイテンシ 1.2〜3.1 秒**に。
- **順序の変更** — 音声駆動は TTS 完了後にしか呼べない。
  `MotionBackend.requires_audio` で分岐し、音声駆動時は
  「TTS → モーション生成 → スケジュール」の順に変更。
  発話 1 本につきモーション 1 本（音声全体を覆うため）。
- **ツール経路の対応** — `generate_motion` ツールも音声を待つ必要があるため、
  要求だけ預けてオーケストレータが TTS 後に拾う形にした。

**効果**
- **無動作率 43.3% → 12.6%**
- 50 秒の説明で **0.0%**（発話全体にジェスチャが乗る）
- **担当発話からのズレ 中央値 28 ms**（①② は 3184 ms）
- モーション尺が音声長と一致（実測 −0.04〜0.00 秒）

## ③ で見えた課題

### 短い発話では動作が間に合わない

`01 挨拶` は ①②（52.5%）より **③ の方が悪い（64.7%）**。
音声駆動は TTS 完了後にしか生成を始められず、レイテンシが 1.2〜3.1 秒あるため、
**1.3 秒の「こんにちは。」には間に合わない**。

対策の候補:
- 短い先頭発話だけ Custom-T2M（テキスト駆動）で先行生成し、以降を音声駆動にする
- 先頭発話の再生をわずかに遅らせる（ただし TTFA が悪化する）
- プランナを vLLM に戻してレイテンシを詰める（論文値は 6 秒ぶんを 0.3 秒）

### レイテンシは論文値に届いていない

1.2〜3.1 秒。プランナを vLLM ではなく transformers で動かしているのが主因と見られる。
ただし vLLM は torch 2.8 系に固定され、バックエンド（Style-Bert-VITS2）と同居できない。
別プロセス・別環境で vLLM を立てれば解決できる。

### 主観評価は未実施

無動作率は「動いているか」の指標であり、
**その動きが発話内容に対して自然か**は測れていない。
③ は音声の韻律から生成しているため、意味的な妥当性は
行動タグ（`动作：挥手打招呼` 等）1 つに依存している。

## 切り替え方法

```bash
# Custom-T2M-Lab（既定）
MOTION_BACKEND=custom-t2m

# SentiAvatar（音声駆動）
MOTION_BACKEND=sentiavatar
SENTIAVATAR_SERVER_URL=http://127.0.0.1:8110
```

SentiAvatar 側は常駐サーバとプランナの 2 プロセスが必要。

```bash
# プランナ（Qwen2-0.5B / vLLM 代替）
CUDA_VISIBLE_DEVICES=1 /opt/sentiavatar-eval/venv/bin/python \
  /opt/sentiavatar-eval/planner_server.py --port 8095 \
  --model_path /opt/sentiavatar-eval/SentiAvatar/checkpoints/llm

# 推論サーバ
CUDA_VISIBLE_DEVICES=1 /opt/sentiavatar-eval/venv/bin/python \
  /opt/sentiavatar-eval/sentiavatar_server.py --port 8110 --planner_port 8095
```

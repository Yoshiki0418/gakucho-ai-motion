## 判明した 4 つの問題

### 1. モーションが発話より先に出る(時間的ズレ)

モーションの開始時刻は「T2M の生成が終わった時刻」で決まっており、音声タイムラインとは無関係。
その結果、**5 回中 3 回は喋り始める前にジェスチャが終わりかけている**。

| シナリオ | モーション | 発話開始に対して |
| --- | --- | --- |
| 01-greeting | 手を振って挨拶 | **−325 ms**(先に発火) |
| 04-no-gesture | うなずき | **−89 ms**(先に発火) |
| 05-consecutive-turns(1ターン目) | 手を振って挨拶 | **−313 ms**(先に発火) |
| 03-multiple-actions | 椅子に座る | +556 ms |

`01-greeting` の `screen-annotated.mp4` を t=25s 付近で見ると、
**MOTION の帯だけが点灯し、SPEAKING がまだ消えている**状態が確認できる。

### 2. 長い応答でまったく動かない

`02-long-explanation` は **50.9 秒の発話に対してモーション 0 回**。
エージェントがツールを呼ばない限りモーションは発生しないため、
1 分近く棒立ちのまま喋り続ける。co-speech gesture が存在しないことの直接的な帰結。

### 3. 複数動作の指示に 1 つしか応えられない

`03-multiple-actions` で「お辞儀をしてから、椅子に座ってください」と指示したが、
発火したのは **「立っている状態から、椅子に座る」の 1 つだけ**でお辞儀は出ない。
フロントエンドが保持するのが単一の `bvhText` なので、構造的に 1 発話 1 モーションが上限。

### 4. モーションの尺が発話長と無関係

`04-no-gesture` は 12.7 秒の発話に対してうなずき 1 回のみ。
モーションの長さは T2M の出力そのままで、発話区間に合わせる仕組みが無い。

## シナリオ別

### 01-greeting — 短い挨拶 + 明確なジェスチャ

- 動画: `01-greeting/screen.mp4`(注釈版 `screen-annotated.mp4`)
- 入力: こんにちは！
- 計測: 発話 2 セグメント / 発話長 3.52s / モーション 1 回
- モーション: 「右手を肩の高さに上げ、手のひらを前方に向けて軽く左右に振って挨拶する」
- 発話開始から **−325 ms** / T2M 生成 737 ms
- 所見: 時間的一致 ✗(先行発火) / 意味的一致 ○(挨拶にふさわしいジェスチャ)

### 02-long-explanation — 長い説明の途中に動作

- 入力: 大学のキャンパスについて詳しく教えてください。
- 計測: 発話 8 セグメント / 発話長 **50.94s** / モーション **0 回**
- 所見: 時間的一致 —(発火せず) / 意味的一致 ✗(説明中ずっと静止)

### 03-multiple-actions — 複数動作の連続指示

- 入力: お辞儀をしてから、椅子に座ってください。
- 計測: 発話 2 セグメント / 発話長 4.94s / モーション 1 回
- モーション: 「立っている状態から、椅子に座る」/ T2M 1440 ms / 発話開始から +556 ms
- 所見: 時間的一致 △ / 意味的一致 ✗(「お辞儀」が欠落し順序も再現されない)

### 04-no-gesture — 動作指示なしの通常応答

- 入力: 今日の天気を教えてください。
- 計測: 発話 3 セグメント / 発話長 12.66s / モーション 1 回
- モーション: 「頭部をゆっくり上下に動かして同意のうなずきをする」/ 発話開始から **−89 ms**
- 所見: 動作指示が無くてもうなずきは出たが、12.7 秒の発話に対して 1 回のみ

### 05-consecutive-turns — 連続ターン

- 入力: こんにちは！ → ありがとうございます。
- 計測: 発話 3 セグメント / 発話長 33.37s / モーション 2 回
- 所見: 各ターンでモーションは出るが、いずれもそのターンの発話開始とは同期していない。
  2 ターン目の「胸に手を当てて感謝を示す」は 1 ターン目の発話開始から +31.8 秒。
  ※ 解析スクリプトはシナリオ内の全発話を 1 区間として扱うため、
  複数ターンでは「発話開始からのズレ」は参考値。ターンごとの評価は動画で行う。

### 06-offline-motion — BVH 直接読み込み(バックエンド不要)

- 計測: 音声なし / モーションは BVH ファイルから直接
- 所見: リターゲット品質の記録用。腕の交差なし・接地正常・プロポーション維持を確認。

## 定性的な所見

- **意味は合っているが時間が合っていない**、という当初の見立てが数値で裏付けられた。
  発火したモーションの内容自体は妥当(挨拶に手を振る、感謝に胸へ手を当てる)。
- 一方で**発話中の大半は無動作**。02 のように 50 秒動かないケースがある。
- T2M の生成時間は 737〜1440 ms と速く、**遅延そのものはボトルネックではない**。
  問題は生成完了時刻をそのまま再生開始時刻にしていること。

## 既知の環境要因(不具合ではない)

- 各シナリオのコンソールエラー 2 件は `/lip-sync/start` `/lip-sync/stop` の 500。
  Ditto リップシンク(127.0.0.1:8080)が未起動なだけで、モーション同期とは無関係。
- 応答本文は動画内のチャット欄で確認できる(`transcript.txt` の保存は本収録の後に実装したため、
  この run には含まれない。次回以降の収録では自動保存される)。

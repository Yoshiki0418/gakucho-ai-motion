### 「お辞儀してから座る」がようやく両方出た

`03-multiple-actions` はフェーズ0まで **1 本しか出せなかった**が、フェーズ1では

- 「立っている状態から、椅子に座る」(予定からの遅れ +32 ms)
- 「腰を前方に曲げて頭を下げ、礼をする」(予定からの遅れ +29 ms)

の **2 本**が別々の時刻に再生された。1 応答 1 モーションという構造的上限が外れている。

### ジェスチャが文中で起きるようになった

タグの位置(`start_offset_ratio`)は当初 0.96〜0.97、つまり句点の直前に固まっていた。
「言い終わってから動く」状態だったため配置の指示を修正し、実測で 0.42〜0.45 まで下がった。
話しながら動く、本来の co-speech gesture に近い挙動になっている。

## 何を変えたか

### 1. インライン行動タグ(項目2)

応答本文に `[act:wave]` のように直接書かせる方式へ変更した。

```
本学の特徴は[act:point]実践的な教育です。ぜひ[act:offer]一度お越しください。
```

- タグは画面にも TTS にも出ない(`extract_action_tags` が除去)
- 1 応答に何個でも書ける → 複数モーション
- 文中の位置を `start_offset_ratio` として保持 → その位置で動く
- ツール往復が無いぶん生成開始が早い

新規: `app/agent/general_conversation/tools/motion_tags.py`
(29 タグの語彙、パーサ、全エージェント共通の指示ブロック)

**指示は 7 箇所すべてに入れる必要があった。** general / ceremony の 2 エージェントに加え、
handoff 先のドメインエージェント 4 つ、さらに **RAG 経路**(エージェントを通らない)。
最初 RAG 経路を漏らしていたため、「大学について教えて」系の質問でだけ一切動かなかった。

### 2. モーションバックエンドの抽象化(項目3)

新規: `app/agent/general_conversation/tools/motion_backends.py`

```
MOTION_BACKEND=custom-t2m   (既定) テキスト → モーション
MOTION_BACKEND=sentiavatar  音声 + 行動タグ → モーション
```

`MotionRequest` / `MotionResult` を境界に置き、`motion_tool.py` 以降のジョブ管理・
SSE 配信・フロントエンドはバックエンドを知らない。
SentiAvatar 側は HTTP アダプタとカタログ ID → 中国語行動タグの対応表まで用意済みで、
ライセンス確認が取れれば環境変数の切り替えで差し込める。

### 3. 途中で見つけて直した不具合

- **タグがチャンク境界で割れる** — ストリーミングでは `…です。[act:` の状態で
  文末の句点が見つかることがある。そのまま確定すると本文として画面と TTS に漏れ、
  モーションも検出されない。タグが閉じるまで文の確定を待つようにした。
  (実際に 1 回目の収録で `[act:point]` が画面に出ていた)
- **同じ動作が 2 回出る** — 行動タグと `generate_motion` ツールの両方から
  同一動作が投入されていた。プロンプトで禁止しても守られないため、
  `MotionJobChannel.claim_prompt()` で応答ごとに 1 度だけに絞る構造にした。

## 残っている課題

### 長い RAG 応答でモーションが出ないことがある

`02-long-explanation`(49 秒の発話)は**この収録では 0 本**だった。
手動検証では同種の質問で 2 本出ており、**モデルの遵守が不安定**という状態。

原因は構造的なもので、いまの方式は「LLM がタグを書いてくれること」に依存している。
検索結果が前段に長く入る RAG 経路では、指示が相対的に埋もれて無視されやすい。

**これは SentiAvatar のような音声駆動 co-speech gesture が構造的に解決する領域**で、
LLM の遵守に頼らず音声波形から常時ジェスチャが出る。フェーズ1の項目4〜5 の意義はここにある。

### 指標の読み替えについて

「担当発話の開始からのズレ」は中央値 135 ms(フェーズ0 は 76 ms)と悪化して見えるが、
これは**タグを文中に置いた結果**であり劣化ではない。
文の 42% 地点に置いたタグは、定義上その位置で発火するのが正しい。

フェーズ1 以降の主指標は **「予定からの遅れ」**(スケジュールした時刻に対する誤差)で、
+11〜140 ms に収まっている。

# Unreal Engine の人型アバターを行動アバターとして適用する

学長の身体モーション（BVH）の表示先は「会話の設定 → アバター・空間」で切り替えます。

| 表示先 | 身体を動かす場所 | 準備 |
| --- | --- | --- |
| ブラウザの3Dビュー | Three.jsで学長のGLBを再生 | 同梱の学長を使用。別キャラクターの追加手順は下記を参照 |
| UE ストリーミング | 実行中のUnreal Editorの学長を再生 | LinuxのUE 5.7で身体受信を起動。[起動手順](#unreal-editorで再生する) |

## ブラウザ用のキャラクターを書き出す

### 1. UE で glTF エクスポータを有効にする

UE エディタ → `Edit` → `Plugins` → "glTF Exporter" を検索して有効化 → エディタ再起動。

### 2. スケルタルメッシュを .glb で書き出す

コンテンツブラウザで対象の SkeletalMesh を右クリック → `Asset Actions` → `Export...`
→ ファイル形式 `.glb` を選択。

エクスポートオプション:

- **Skeletal Meshes: ON**(必須。スケルトンが無い glb は読み込み時にエラーになる)
- Export Vertex Skin Weights: ON
- Bake Material Inputs: `Simple` 以上(テクスチャを残したい場合)
- アニメーションは不要(モーションは BVH 側から与えるため)

MetaHuman の LOD0 はポリゴン数が非常に多くブラウザでは重いので、LOD2〜3 相当か、
簡略化したメッシュを書き出すこと。

> **ライセンス注意**: MetaHuman は Epic のライセンス上、UE / Twinmotion 以外の
> エンジンでの利用に制限がある。第三者へ配信する用途で使う前にライセンス条件を確認すること。
> UE5 マネキン(Manny / Quinn)や自作・購入アセットには通常この制限はない。

### 3. リポジトリに置く

```
frontend/public/avatars/<好きな名前>.glb
```

置くだけで `/avatar-list` が拾い、ビューア右上のアバターセレクタに自動で並ぶ。

### 4. 確認する

1. フロントエンドを開く
2. アバター領域下部の **🧸 キャラ** を押す
3. 右上のセレクタで置いた glb を選ぶ
4. チャットで動作を指示する(例: 「手を振って」「椅子に座って」)

サーバーに置く前に試したいときは、右上の **📁 UE 書き出しの .glb を開く** から
ローカルファイルを直接読み込める。

## うまく表示されないとき

| 症状 | 原因と対処 |
| --- | --- |
| 横 / 後ろを向いている | 正面は腰・両腿・上体から自動判定される(`autoYawDegrees`)。それでもズレる場合は右上の「向き」で追加調整する(自動判定値への加算) |
| 宙に浮く / 床にめり込む | 靴底がレスト姿勢で床に来るよう自動接地する(`groundOffset`)。BVH 側も「足が床に接する腰の高さ」を基準にルート移動を転写する |
| 棒立ちのまま動かない | ボーン対応が取れていない。DevTools のコンソールで `[characterRig] bound N bones` を確認。N が 10 未満ならリグが想定外の命名。`humanoidBones.ts` の `SIDE_ALIASES` / `CENTER_ALIASES` に実際のボーン名を足す |
| `SkinnedMesh がありません` | スケルトン無しで書き出している。手順 2 の Skeletal Meshes を ON に |
| 巨大 / 極小になる | 高さは BVH 骨格に自動フィットするので通常は起きない。起きる場合はメッシュに想定外のスケールが乗っている |
| 真っ白になる | テクスチャ無しのモデルは意図的に白の素体表示にしている(`BODY_COLOR`)。テクスチャ付きで書き出せば元の見た目が保持される |

## 仕組み(実装メモ)

`characterRig.ts` のリターゲットは 2 段構えになっている。

### 1. バインド時: レストポーズを BVH の T ポーズへ合わせ込む

UE のスケルトンは **A ポーズ**(腕が約 50 度下がった状態)がレストで、BVH は **T ポーズ**。
「各リグ自身のレストからの差分」をそのまま渡すと、BVH が T ポーズから腕を下ろす回転量に
UE 側の A ポーズ分がそのまま上乗せされ、**腕が下がりすぎて体の前で交差する**。

そこで `alignRestToSource()` が、ボーンごとに「子ボーンへ向かう方向」が BVH のレストと
一致するよう最小回転をかけ、親から順に適用する。回転しか変えないので骨の長さや
左右の間隔は保たれる。この揃えた姿勢を転写の基準にする。

子が複数ある腰・胸は向き合わせが一意に決まらないため対象外(リグが違ってもほぼ直立で
揃っているので問題ない)。学長 v3 では 38 ボーン・最大 44.9 度の補正が入る。

### 2. 毎フレーム: 絶対姿勢でマッチングする

```
D_src = W_src_now · W_src_rest⁻¹        // 祖先の回転も含んだ絶対差分
q_dst = P_dst_now⁻¹ · D_src · W_dst_rest_aligned
```

`links` は親が先の順に並べてあり、親を解いた結果をそのまま子の計算に使う。
差分を**絶対量**で受け渡すため、片方のリグにしか無い中間ボーン
(Mixamo に無い `Neck1`、UE の `spine_04` など)があっても取りこぼさない。

これで次の 4 つの差異を同時に吸収できる。

- **ボーン名**: `humanoidBones.ts` が Mixamo / UE / VRM の命名を共通の正規名へ寄せる
- **ボーン軸**: UE はボーン長手方向が X、Mixamo は Y
- **レストポーズ**: T ポーズ / A ポーズ の違い(上記 1.)
- **階層の段数**: 中間ボーンの有無(上記 2.)

回転のみを渡し、骨の長さや左右間隔はモデル本来の値を使うため、プロポーションは崩れない。
腰の移動量だけは別途スケール換算して転写している(座る動作の接地に必要)。

### 接地と向き

- **接地**: BVH の Hips は OFFSET が原点(y=0)だが、モーションデータは実際の腰の高さ(約 0.93)を
  position チャンネルで持つ。素のレスト位置を基準にルート移動を転写すると、その腰の高さが
  まるごと差分として乗り、キャラクターが脚の長さぶん浮く。`groundedRootPosition`
  (レスト姿勢で最下点が床に来る腰の位置)を基準にすることで解消している。
  加えてモデル側も、レスト姿勢での最下点(`groundOffset`)を引いて床へ降ろしている。
- **向き**: 腰から上体への `up` と、右腿から左腿への `right` の外積で体の正面を求め、
  BVH と揃うのに必要な Y 回転を `autoYawDegrees` として自動算出する。
  T ポーズ合わせ込みは各ボーンの振りしか直さず体軸まわりの捻りは触らないため、
  正面の判定はこの体フレームから別途行う必要がある。

### 既知の制限

モデル側に中間ボーンが無い場合(例: `character.glb` には `Neck1` が無い)、
各ボーンの**向き**は BVH と厳密に一致するが、3 関節を 2 関節で再現することになるため
チェーン全体の**形**はわずかにずれる。頭の向き自体は正しいので実用上の影響は小さい。

学長アバター(v1 / v3)は BVH と同じ段数のスパイン・ネックを持つため、この制限に当たらない。

## Unreal Editorで再生する

1. アプリと同じLinuxホストでUE 5.7の学長プロジェクトを開き、学長のシーケンス `FOR_GAKUTYO_AI` を再生します。受信処理は、このシーケンスにスポーンされた `Body` とその骨格に対応するアニメーションセクションを使用します。
2. リポジトリのルートで `python3 tools/ue-body-motion/bridge_path.py` を実行し、共有ディレクトリを作成します。`tools/start-system.sh` も起動時にこれを実行します。既存環境を更新する場合はフロントエンド・バックエンドの新しいコードと、backend・nginxのCompose設定を反映してください。
3. UEで Pixel Streaming 2 と Python Editor Script Plugin を有効にします。「Tools → Execute Python Script」で、このリポジトリの `tools/ue-body-motion/start_editor.py` を実行すると、身体受信と学長用カメラが起動します。再起動時も有効にするには、Python Editor Script Plugin の「Project Settings → Plugins → Python → Startup Scripts」に同じファイルの絶対パスを追加します。
4. 次のコマンドで身体受信の `ok` と既存の顔制御の `sequence_playing` がともに `true` であることを確認します。公開先と証明書の場所は環境に合わせてください。

   ```sh
   curl --cacert nginx/certs/server.crt https://192.168.29.19:30930/api/ue-motion/health
   curl --cacert nginx/certs/server.crt https://192.168.29.19:30930/lip-sync/health
   ```

5. 「会話の設定 → アバター・空間 → UE ストリーミング」を選んで設定を閉じると、学長の頭から腰までの映像が自動で表示されます。「手を振りながら挨拶してください」などの指示を送り、身体の動きと口パクを確認します。生成方式は「会話の設定 → 動作生成」で変更できます。

### 再生経路

ブラウザは音声の再生位置を基準に、動作の版・経過時間とBVHを `POST /api/ue-motion/play` に送ります。APIはLinuxホストのUnixソケットに中継し、UEは学長の基準姿勢に合わせた一時アニメーションをBodyで再生します。動作が終了するか、会話を中断するか、表示を切り替えるとBodyの元の設定に戻ります。FaceのControl Rigは既存の口パクに使用します。

会話中の挨拶・指差し・うなずきでは、画面に出ている待機姿勢に身振りを重ねます。腰の位置と脚の姿勢を保ち、頭と胴の振れ幅、腕の回転速度を抑えます。左右の肘は学長の骨格に合わせて曲げ、肩で手先の方向を合わせます。胸元を通る動作では、ジャケットの寸法に合わせた近似形状で両腕の前腕・手首・手のひら・指先を確認し、服の内側に入る姿勢を補正します。お辞儀・着席・歩行など、全身を使う動作は腰と脚も再生します。

UEが準備済みの区間を連続再生している間に、次の区間の姿勢をバックグラウンドで計算します。UEエディター側では骨のトラックを少しずつ登録し、音声の経過時間に再生位置を合わせます。新しいクリップや音声リズムの更新が届いたときも、次の区間の準備中は表示中の動きを続けます。中断時は最後に表示した姿勢から約0.3秒で待機姿勢に戻ります。

UEの学長はすべての視聴者で共通です。複数のタブから送信したときは新しい動作が再生を引き継ぎます。ほかのタブを閉じても再生中の動作は続きます。

学長用カメラはシーケンスのBodyの頭・肩・腰から正面の構図を決め、専用の配信名 `GakuchoPortrait` で映像を送ります。視聴中だけ継続して描画します。エディターのビューやSequencerの操作は会話画面に映りません。

### 接続の確認

- **身体受信が503を返す** — エディターで起動スクリプトを実行し、backendコンテナに `/tmp/gakucho-ai-motion-ue/bridge` がマウントされていることを確認します。ホスト側の配置を変えるときは、エディターとComposeで同じ `GAKUCHO_UE_BRIDGE_DIR` を指定し、親ディレクトリを実行ユーザー専用にします。
- **「学長のカメラに接続できません」と表示される** — 学長のシーケンスを再生し、起動スクリプトを実行してから「再接続」を押します。カメラのシグナリング接続先は既定で `ws://127.0.0.1:8899` です。配信サーバーのStreamer用ポートが異なる場合はUE起動前に `GAKUCHO_UE_SIGNALLING_URL` を設定します。
- **映像または口パクが届かない** — Linuxのnginx構成では、Pixel Streamingの映像・WebSocketはホストの8080番、顔制御は8081番です。
- **身体再生が422を返す** — 開いているシーケンスのBodyと互換アニメーションセクションを確認します。詳細はUEのOutput Logに出ます。

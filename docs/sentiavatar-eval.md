# SentiAvatar 評価レポート（フェーズ1 項目4・5）

- 実施日: 2026-08-25
- 判断: 学校法人での研究評価として非商用条項の範囲内と整理し、推論のみで導入
- 設置場所: `/opt/sentiavatar-eval/`（リポジトリ外。非商用ライセンス成果物を混在させないため）

## 結論

**日本語音声でも問題なく動作した。** 中国語 HuBERT を音声エンコーダに使うため
日本語は分布外になるが、生成が縮退する兆候は見られなかった。
むしろ既存の Custom-T2M-Lab より**音声との時間整合が決定的に良い**。

| 観点 | Custom-T2M-Lab | SentiAvatar | |
| --- | --- | --- | --- |
| 入力 | テキストのみ | **音声 + 行動タグ** | 音声を見るかどうかが本質的差 |
| 尺の音声一致 | −1.45 〜 −6.27 s | **−0.04 〜 0.00 s** | 決定的 |
| 動きの量(フレーム間変化) | 0.003〜0.022 | **0.025〜0.111** | 4〜30倍 |
| 出力スケルトン | Mixamo 命名 55 ボーン | **UE 命名 63 ボーン** | 学長アバターと同系統 |
| 生成時間 | 0.66〜0.72 s | 数秒(評価構成) | 下記の注記参照 |

## 1. 尺が音声に一致する

これが最大の差。Custom-T2M-Lab は**入力に関係なく常に 2.57 秒**を返す。
発話が 8.84 秒でも 2.57 秒しか動かない。

| ケース | 音声 | Custom-T2M | 差 | SentiAvatar(補正後) | 差 |
| --- | --- | --- | --- | --- | --- |
| ja_greeting | 4.02 s | 2.57 s | −1.45 s | **4.00 s** | −0.02 s |
| ja_explain | 8.84 s | 2.57 s | −6.27 s | **8.80 s** | −0.04 s |
| ja_thanks | 4.10 s | 2.57 s | −1.53 s | **4.10 s** | 0.00 s |

### 見つけた不具合: BVH の Frame Time が誤っている

素の出力は音声より**一律 1.5 倍長い**。原因は SentiAvatar 側の BVH ライタで、

- 実際のモーションは **30 fps**（同時出力される JSON も `fps: 30`、frames ÷ 音声秒 = 29.9〜30.0）
- しかし BVH ヘッダは **`Frame Time: 0.050000`（20 fps 相当）**で固定

中国語のデモ音声でも同じ 1.50 倍になるため、**日本語固有の問題ではない**。
`Frame Time` を 0.033333 に直せば音声長と 0.04 秒以内で一致する。
`motion_backends.py` の `fix_bvh_frame_time()` で読み込み時に補正するようにした。

## 2. 日本語音声でも縮退しない

音声エンコーダは中国語 HuBERT（`checkpoints/chinese-hubert-base/`）なので、
日本語 TTS の音声は分布外になる。棒立ちの縮退が出ないかを動きの量で確認した。

| 音声 | 動きの量 |
| --- | --- |
| 中国語デモ（分布内） | 0.088 |
| 日本語 ja_greeting | 0.025 |
| 日本語 ja_explain | 0.100 |
| 日本語 ja_thanks | 0.111 |

日本語は 0.025〜0.111 で、中国語デモの 0.088 と同じ範囲に収まっている。
**分布外による破綻は起きていない。**

ただしこれは「動いているか」の指標であり、**日本語の韻律に対して動きが意味的・
リズム的に適切か**までは測れていない。人間による主観評価が別途要る。

## 3. スケルトンが UE 命名

```
pelvis, spine_01..spine_05, neck_01, neck_02, head,
clavicle_l, upperarm_l, lowerarm_l, hand_l, thigh_l, calf_l, foot_l, ball_l, ...
```

学長アバターと同じ UE 系命名で、**既存のリターゲット層がそのまま使える**。
Mixamo 命名の Custom-T2M-Lab を扱えるようにしてあるので、
どちらのバックエンドでも学長アバターを駆動できる。

## 構成上の判断

### vLLM を使わずに立てた

公式構成は LLM プランナ（Qwen2-0.5B）の推論に vLLM 0.11 を使うが、
vLLM は torch 2.8 系に固定される。この環境は torch 2.12 / transformers 5.10 で、
**バックエンド（Style-Bert-VITS2）を壊さずには同居できない**。

そこで
- 隔離した venv（`/opt/sentiavatar-eval/venv`、torch 2.8 + transformers 4.57）を作り、
- プランナは vLLM ではなく素の transformers で動かす等価サーバ
  （`/opt/sentiavatar-eval/planner_server.py`）に差し替えた。

`/text_to_motion` と `/health` の入出力を公式の `vllm_server.py` と同一にしてあるため、
`single_case_infer.py` からは区別が付かない。0.5B と小さいので評価用途では速度も足りる。

### 生成時間について

評価構成では 1 本あたり数秒かかっている。ただしこれは
**毎回モデルをロードし直す `single_case_infer.py` を都度起動している**ためで、
論文の「6 秒ぶんを 0.3 秒」はモデル常駐時の値。
本番接続するならモデル常駐の HTTP サーバにする必要がある
（`SentiAvatarBackend` はその前提で `/generate` を叩く実装にしてある）。

## 本番へ接続する場合に残っている作業

1. **常駐推論サーバの実装** — `single_case_infer.py` の処理をモデル常駐の
   HTTP サーバ（`/generate`、`/health`）に組み直す。`SentiAvatarBackend` はこの
   インターフェースを前提に実装済み。
2. **音声を先に確定させる必要がある** — SentiAvatar は音声駆動なので、
   現在の「モーションを TTS より先に投げる」流れは使えない。
   TTS 完了 → SentiAvatar 生成 → 再生、の順に変える必要がある。
   フェーズ0 のスケジュール機構はそのまま使えるが、モーションの到着が
   発話再生開始より遅れうるので、先頭発話の再生を少し待つ調整が要る。
3. **主観評価** — 日本語の韻律に対する自然さは数値では測れていない。
4. **ライセンスの継続確認** — 研究評価を超えて本番運用する場合、
   非商用条項（営利組織の内部業務・本番システムでの利用を禁止）の再確認が必要。
   商用照会先: legal@sentipulse.com

## BVH 出力の問題と対応（2026-08-26 追記）

学長アバターへ実際に接続したところ、アバターが動作タイミングで画角から消えた。
調べた結果、**原因は 2 つだけ**だった（当初 5 つの別々の不具合と見立てたが、
うち 3 つは 1 つ目の症状が波及したものだった）。

| # | 問題 | 影響 |
| --- | --- | --- |
| 1 | `Frame Time` が 20fps 固定（実体は 30fps） | 尺が一律 1.5 倍になり音声とずれる |
| 2 | **HIERARCHY の OFFSET が UE のボーンローカル値のまま** | レストが「一直線ポーズ」になる |

### 2 が波及して起きていたこと

UE のボーンは**長手方向が X** で、`ue_ours_offset_from_fbx.json` の OFFSET は
その親ボーンローカル系の値（例: `spine_01` → `[1.40, -0.24, 0.0]`）。
これを BVH の OFFSET にそのまま書くと、全回転 0 のレストが
**全ボーンが体軸上に一直線に並んだ姿勢**になる。UE では各ボーンのレスト回転が
姿勢を作るが、BVH には回転を書く場所がないため落ちてしまう。

本プロジェクトのリターゲットも、スケールも、軸判定も、すべて**レスト姿勢を基準に測る**。
そのため壊れた基準が連鎖して、別々の不具合に見える症状を生んでいた。

| 見えていた症状 | 実際の原因 |
| --- | --- |
| 骨格が約 117 倍 | 一直線レストの「全高」＝全ボーン長の総和になっていた |
| キャラが画角外へ飛ぶ | 上記スケールで、ルート移動が身長 6 個ぶんの高さへ換算されていた |
| 骨格が横倒し（Z-up に見えた） | レストの「腰→頭」が (1,0,0) だったため、Y-up 判定が誤っていた |
| 姿勢が崩れる | `alignRestToSource` が壊れた基準へ合わせ込んでいた（補正量 176.7 度） |

**各フレームのデータ自体は最初から正しかった。** 元 BVH を素の FK にかけると
Y-up・身長 157cm・骨盤 102cm・足が接地した、正常な人体姿勢が得られる。

### 対応: レストをモーション 1 フレーム目へ組み直す

`/opt/sentiavatar-eval/bvh_rebase.py` で BVH を読み直し、レスト＝1 フレーム目になるよう
階層を組み直してから返す（推論サーバ側で完結。リポジトリ側の変更は不要）。

```
OFFSET_i := P_i(0) - P_parent(0)                      (ワールド座標のまま置く)
L'_i(t)  := G'_parent(t)⁻¹ · G'_i(t),  G'_i(t) := G_i(t) · G_i(0)⁻¹
```

全回転 0 のレストが 1 フレーム目の立ち姿に一致し、かつ**任意フレームのグローバル関節位置は
元 BVH と厳密に一致する**（実測の最大誤差 0.0027 mm ＝ 小数 6 桁の丸め相当）。
ボーン長も左右間隔も変わらない。あわせて cm → m へ換算し、`Frame Time` も 1/30 で書き直す。

結果、新しいレストは 腰→頭 (0.01, 1.00, 0.06) / 左腿 (−0.07, −1.00, −0.01) / 全高 1.571 m。
フロント側の `reorientBvhAxes`・`normalizeBvhScale` はどちらも自動的に no-op になる。

### 中国語のまま動かした結果

学習は中国語のまま、日本語 TTS 音声を入れて生成したときの手・頭の移動量:

| 入力 | 動作タグ | 手の可動範囲 | 頭の可動範囲 |
| --- | --- | --- | --- |
| 中国語 公式デモ音声 | 挥手打招呼 | **0.648 m** | 0.067 m |
| 日本語 説明 | 说明 | 0.554 m | 0.157 m |
| 日本語 お礼 | 鞠躬感谢 | 0.215 m | **0.242 m**（お辞儀） |
| 日本語 挨拶（4 秒） | 挥手打招呼 | 0.030 m | 0.036 m |

日本語音声でも中国語デモと同等の振幅が出るケースがあり、動作タグの意味も反映されている
（お礼では頭の動きが最大＝お辞儀）。一方で短い挨拶はほぼ静止した。
音声エンコーダが中国語 HuBERT である影響は、この振幅のばらつきとして出ている可能性が高い。

生成レイテンシは 1 本あたり 3.1 秒（4〜7.4 秒のモーション）。

### 実機収録（中国語学習のまま）

`docs/sync-baseline/recordings/20260826-143247-sentiavatar-zh2/`

レスト再構築後、学長アバター(gakucho_v3_suit)へ接続して全シナリオを収録した。
アバターは正常に表示され、直立・正面・接地する。**動作タイミングでの消失は解消**。

リターゲットのログも健全になった。

| 指標 | 修正前 | 修正後 |
| --- | --- | --- |
| リグ判定 | `mixamo-like`（誤判定） | `unreal` |
| レスト合わせ込みの補正量 | 176.7 度 | 32〜40 度 |
| ルート基準高さ | 0.000 | 1.020 |
| 骨格の全高 | 220（＝全ボーン長の総和） | 1.6 |
| ルート位置 | 画角外へ | `[0.00, 1.01, 0.00]` |
| スケール/軸の補正ログ | 発生 | 0 件（どちらも no-op） |

同期の測定結果:

| | Custom-T2M（③調整後） | SentiAvatar |
| --- | --- | --- |
| モーション回数 | 16 | 12 |
| 担当発話開始からのズレ 中央値 | 3184 ms | **136 ms** |
| 発話前に発火 | 0 | 0 |
| 発話後に発火 | 0 | 0 |
| 無動作率 | 43.3% | **27.3%** |

無動作率はシナリオごとの応答長・ルーティング（RAG 経路は設計上モーションなし）に
左右されるため、run 間の直接比較には幅がある。一方**担当発話開始からのズレ**は
音声駆動である SentiAvatar が明確に優位（3184 ms → 136 ms）。

残る弱点は**生成レイテンシ 3.1 秒**で、短い先頭発話に間に合わない。
01-greeting では発話開始から +1701 ms 遅れ、担当発話ではなく次の発話中に再生された
（無動作率 67.2%）。長い応答（02、49 秒）では 6 回発火して 8.4% まで下がる。

### 副次的に見つかったバグ（修正済み）

読み上げ本文が空白だけになった文をそのまま TTS に渡すと
`ValueError: 入力テキストが空です。` で **SSE ストリーム全体が落ちる**。
行動タグだけの文（`[act:wave]` など）でタグ除去後に本文が消えると踏む。
`backend/app/routers/text_chat_router.py` の空判定を `strip()` ありに直し、
本文が消えた文の行動タグは次の発話へ持ち越すようにした（`carried_tags`）。
これで 1 収録あたり 4 件出ていた同エラーが 0 件になった。

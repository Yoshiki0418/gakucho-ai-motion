# 学長AIの住宅動作と物理学習をClaudeへ引き継ぐ資料

2026年10月15日時点。対象リポジトリは `/gpu-server/yamamoto/gakucho-ai-motion`。Claudeが背景・実装・実験結果を理解し、次の改善を検討するための共有資料です。本文だけでも現状を把握できます。コードや評価を再実行する場合は、リポジトリと `.runtime` 内のモデル資産が必要です。

現在は4段階のうち**フェーズ2の家具回避を検証中で、未合格**です。学長体格の基本動作と、実深度画像を使う上位判断モデルは実装・学習済みですが、任意の住宅で動ける状態ではありません。直近はGPUで追加学習と原因分析を行い、改善しなかった候補を不採用にしました。維持した基準モデルは、新しい32配置で**成功6/32、接触終了26件**でした。この物理学習モデルは、会話中の住宅アバターへまだ接続していません。

## ユーザーの目標と経緯

最初は、学長AIの応答は返るのにアバターの動作が合わないこと、動作が勝手に速く見えること、T2Mへの指示と実際の動作が一致しないことを調査していました。その後、何もない検証空間に加えて写真のようなリアルな住宅を作り、椅子への移動・着座やキッチンへの移動を試す方向へ進みました。

最終目標は、固定経路や特定の家具配置に依存せず、**形状や家具配置が異なる3Dの部屋でも、観測をもとに歩行・回避・着座などを選んで実行できること**です。実世界のカメラ映像からのロボット制御は、現段階の対象ではありません。GPUの積極利用と自律的な検証・改善はユーザーから許可されています。

以前のT2M指示ログ、フィラー設定、初期位置の浮きなどは別の調査履歴です。この共有時点の物理実験から、それらの現在の設定や解決状況まで断定しないでください。

## 身体と物理の前提

表示アバターは `frontend/public/avatars/gakucho_v3_suit.glb`。実GLBを採寸した `frontend/public/world-model/gakucho-avatar-profile.json` から、物理用の骨格・脚・靴底・頭部・骨盤の接触形状を合わせています。表示の頭頂までの高さは約1.825 mです。物理体節の総質量64.7 kgは既存の物理側の仮定で、GLBからの測定値ではありません。スキン全頂点と接触形状が同一という意味でもありません。

内部座標はZ-up、前方−Y、単位m・kg・s。表示への変換は `(x,y,z) → (x,z,-y)`。身体の自由位置はreset時だけ設定し、実行中は関節トルクと物理積分で動きます。身体位置の直接補正、最終目標の付け替え、外力による経路追従で成功を作りません。sceneの箱寸法とnative MuJoCoの `geom_size` の半寸法を混同しないでください。

ここで「世界モデル」と呼んでいるのは重力・剛体・接触を計算する物理環境です。ニューラルな未来予測モデルを学習済みという意味ではありません。

## 現在の視覚モデルと関節制御

| 項目 | 仕様 |
| --- | --- |

| 上位方策の入力 | 深度3フレームと局所目標・身体状態11値。地図・教師経路・形状IDは渡さない |
| 上位方策の出力 | 向きと歩調・停止の2値を100 msごとに選ぶ |
| 下位方策の入力 | 110値。関節・身体・指令に加え、実形状の距離・床面など51特徴を含む |
| 下位方策の出力 | PD関節目標へ加える制限付き20関節補正。20 msごとに制御 |
| 物理と接触監査 | 2 msごとに積分・接触監査。一度の家具・壁接触も履歴に残す |
| T2Mとの関係 | 保存したT2M歩行の周期・参照を物理制御の土台に使用。各時刻の行動全体をT2Mへ問い合わせる方式ではない |

上位は実深度画像を使いますが、下位は51個の形状センサー特徴も利用し、目標・姿勢はシミュレータ由来です。全身の画像だけによる制御、RGB認識、画像からの自己位置推定、長期地図記憶、実カメラへの対応は実現したと扱いません。

実装は `depth_perception.py`、`visual_navigation.py`、`visual_policy.py`、`command_motor.py`、`command_gait.py`。幾何教師は訓練データ生成や原因分析用です。推論時に全形状・教師経路を渡す診断と、学習済み視覚方策の結果を分けます。旧 `command_navigation.py` の112入力上位と、現在の深度画像上位も区別してください。

## 直近の原因分析と追加学習

v4とv5は元の5aaから別々に開始した試行で、元のactor・critic・標準偏差・Adam・カウンタを保持した開始を監査しました。GPU 0のRTX A6000で合計**335,872実制御・3,358,720物理積分・820追加PPO epoch**を実行しています。教師収集33,216制御、原因分析38軌跡・22,033制御・220,330物理積分は、PPO学習数へ加算していません。

## 基準モデルを固定して確認した新32配置

追加候補を不採用にし、R4上位＋5aa下位・CPU推論を固定してから成績を開示しました。**追加学習で改善したという前後比較ではなく、維持モデルの別配置への汎化評価です。**

| --- | ---: |
| 回避・到達・停止・歩容など全gate成功 | 6/32（18.75%） |
| 記録終了まで転倒なし | 32/32 |
| 無接触 | 6/32 |

歩行条件の残る3件は早期接触で前進0.8 mに届かなかったものです。`walkingVerified` や `physicalRepeatedGait` は到達判定も含むため、その値だけから歩行リズムが壊れたと判断しないでください。接触時に終了する評価なので、転倒なし32/32は長時間の耐転倒性を示しません。

scene seedは1182000〜1182031、physics seedは3182000〜3182031、難易度0〜0.5、最大30秒。CPU・Torch 1 thread、spawn 4 workerで、実14,440関節制御・144,400物理積分・2901上位判断でした。全32のnative軌跡、初期qpos・qvel・深度・状態・目標、保存30ソースを独立再監査しました。

初回の32件では実消費した最初の方策出力を保存していません。保存した実初期入力からCPU再計算した行動と、「当時の実消費行動の記録」を区別してください。旧8配置のv5比較では、実際の最初の行動も保存して上位の一致を確認しています。

## 制御インターフェースの制約と次の案

現行の上位歩調は、歩行用lookahead0.35〜0.50 mと停止を切り替えます。下位の速度目標は指令距離から決まり、停止で距離が0になると横方向の指令角も失われ、yaw速度目標も0になります。そのため、**停止しながら曲がる、その場で向きを変えるという独立した要求を表現できません。** ゴール近傍以外で、ごく低速な前進を指定する範囲も不足しています。

下位の目標yaw速度は最大±0.135 rad/sですが、これは報酬の追従目標であり、実旋回速度の物理的上限ではありません。根拠は `command_motor.py` の `observed_command_angle` と報酬計算、`visual_navigation.py` のlookahead契約です。

次に検討する案は以下です。**独立速度・yaw指令はまだ実装・学習していません。**

1. 前進速度と旋回速度を独立して渡す新しい観測・制御契約を設計する。旧110入力と同じ意味だと偽ってcheckpointを流用しない。
2. 同じ学長体格で直進・左旋回・右旋回・減速・停止・その場旋回を学習する。既存動作の再現や保持を組み込み、片側だけの改善と他技能の退行を個別に判定する。
3. 両方向の追従・停止・接触・反復歩行を開発条件で通過した下位モデルを先に固定する。
4. そのモデルで物理成功した訓練用軌跡を収集し、上位の視覚判断を追加学習する。
5. 構成を固定して新たな未使用配置で評価する。フェーズ2通過前に、複数部屋・階段を習得したとは扱わない。

失敗原因をこのインターフェースだけに断定してはいません。必要な指令を表現できることと、学習で家具回避が改善することは、別々に検証する必要があります。

## 再調査で避けたい取り違え

- **時間入力の不一致という仮説は撤回済みです。** 8秒学習と30秒評価の違いを疑いましたが、継承先の `ReferenceHumanoidEnv` が最後の基底特徴を歩行参照位相に置き換えています。初期状態、先頭50の実入力・実出力、8秒分80物理サンプルの一致も確認しています。
- 下位5aa、報酬v4、報酬v5は同じ110/20 shapeでも契約が異なります。validatorを無効化して混在させず、`tracked_visual_navigation.py` の明示的な転送と検証を利用してください。
- 元29ソースと元モデル、身体、モーション資産、公開manifestのSHAは実験前後で一致しています。改修時は既存試行のソース原本と結果を保持し、新しい出力先と契約・来歴を作ります。
- 旧8配置、原因分析の4配置、今回開示した32配置は既に成績を見ています。今後そこでモデルを選ぶなら開発扱いにし、最終評価には別の未使用配置を確保してください。1800000〜1999999は今回の視覚実験では使っていませんが、同範囲には過去の方向転換課題で使用したseedもあります。範囲全体が履歴上未使用とは仮定しません。
- 全形状を知る教師、ルール経路、物理的な補助、学習済み視覚モデル、単独PPOの結果を区別してください。2方策混合も「新しい単一モデルの学習」ではありません。

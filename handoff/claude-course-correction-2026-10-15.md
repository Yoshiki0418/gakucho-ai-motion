# 軌道修正の方針と実施記録（Claude, 2026-10-15）

[引継ぎ資料](claude-2026-10-15.md) と、ユーザーが共有した「T2M＋物理追従器」構成の助言をもとに、Codexの作業を見直した結果です。既存の成果物（R4・5aa・公開manifest・評価記録）は一切変更していません。新しい作業はすべて `world_model/tracker/` と `.runtime/world-model/tracker/` に分離しています。

## 1. 結論

- フェーズ2の失敗の主因は、視覚判断よりも**下位制御が片方向にしか曲がれないこと**だと、既存の記録から数値で確認できました（2章）。
- ただしより大きな問題は構成そのものです。現行の下位制御は「手設計のIK歩容＋小さな残差PPO」で、20関節（胴体ヨー・肩ヨー・首・手首なし）の身体です。この形では、学習済みの日本語T2Mが出す100種類の日常動作（座る、寝る、拾う、手を振る…）を物理で再現できず、**研究の核であるT2Mが物理側にほぼ接続されていません**（歩行周期の参照にだけ使用）。
- そこで助言の「方式A」に沿って、**T2M/モーキャプと同じ骨格・学長の実寸を持つ全身の物理追従器（PHC型）を、GPU大規模並列で学習する**方向へ切り替えました。移動はこの追従器に「経路に沿った参照動作」を与える形で解き、視覚は特権情報で成功してから教師・生徒学習で載せます。

## 2. 現状の診断（観測事実）

対象：Codexが開示済みの新32配置（R4上位＋5aa下位、CPU推論、成功6/32）のnative軌跡。解析スクリプトは会話中のscratchpadで実行し、元データは変更していません。

| 確認内容 | 結果 |
| --- | --- |
| 指令の向き（上位が要求した方位オフセット）と実際の旋回（1秒窓、530窓） | 右旋回の要求（-0.5〜-0.3 rad）：実yaw -0.132 rad/s（目標 -0.125）。**左旋回の要求（+0.3〜+0.5 rad）：実yaw +0.025 rad/s（目標 +0.124の約2割）**。全体に右向きの偏り -0.045 rad/s |
| 家具のどちら側を通ったか（家具の横を通過した時点、または終了時の位置） | **右側（−X）を回った17件は全件失敗**、左側（+X）を回った15件は6件成功。32件中30件は最短経路と同じ側を選択 |
| 既存の接触診断（全形状を知る幾何教師） | 旋回要求中の実yawの符号が要求と逆の割合が約45〜50%、平均実yawは要求と逆符号 |
| 配置の難しさ（単輪モデルでの到達可能性、体半径0.25 m） | 実測に近い v=0.22 m/s・ω=0.2 rad/s で **32/32が衝突なしに到達可能** |
| 学習規模 | 追加PPOは合計約34万制御ステップ（8 CPU環境）。人型の全身制御で一般的な規模（10^8〜10^9）より3桁少ない |

※ 内部座標はZ-up・前方−Yで、+Xが身体の左、yaw増加が左旋回です。左右の旋回能力の差と、通過側による成否の偏りはいずれも観測事実ですが、両者を結ぶ因果（どの時点のどの旋回が不足して接触したか）までは今回確定していません。

解釈：家具配置は運動学的には十分解ける難しさで、視覚より先に「指令どおりに左右へ曲がれる下位制御」が欠けています。Codexが次案として挙げていた「前進速度とyaw速度の独立指令」は方向として正しいものの、現行の残差＋IK歩容の枠内で少量のPPOを重ねても解決しにくいと判断しました。

## 3. 方針（助言の方式Aに準拠）

```
日本語指示 ─→ LLM/VLMで部分目標へ分解（後段）
                 ↓
経路計画（最初は特権地図のA*、後に深度から作る地図）
                 ↓ 経路
参照動作の生成（T2M・モーキャプの歩行を経路に沿って配置／T2Mの着座など）
                 ↓ 運動学的な参照
全身物理追従器（今回新規、GPU学習）  ← ここが最重要の土台
                 ↓ 関節トルク（PD）
MuJoCo（既存のフェーズ2評価・接触監査を再利用）
```

| 項目 | 変更前（Codex） | 変更後 |
| --- | --- | --- |
| 身体 | 20関節の簡略人体 | T2M/モーキャプのBVH骨格（指を除く）×学長の実寸。22体節・63関節自由度、64.7 kg、頭頂1.825 m |
| 下位制御 | 手設計IK歩容＋±0.35 rad以内の残差PPO | 参照動作への残差（±0.5 rad）を出す全身追従方策。歩行・旋回・着座・起立などを単一方策で追従 |
| T2Mの役割 | 歩行周期の参照のみ | 生成した動作そのものを物理で再現する |
| 学習環境 | MuJoCo CPU、8並列 | MuJoCo Warp（GPU）、8192並列。毎秒6〜9万制御ステップ |
| 移動・回避 | 深度画像から上位方策を強化学習 | 経路計画＋参照生成＋追従。視覚は特権情報で成功した後に蒸留 |
| 評価 | 既存のフェーズ2評価 | 同じ評価・接触監査を再利用。追従器自体はGPUと別エンジン（CPU MuJoCo）で独立評価 |

## 4. 今回実施したこと

1. **全身追従用の身体** `world_model/tracker/body.py`：学長アバタープロファイルのT姿勢関節位置から構築。各体節は静止時に世界座標と平行なので、BVHの局所回転が座標変換だけで関節角になります。足は実測の靴形状を踵と爪先に分割。PDで静止姿勢を4秒保持できることを確認。
2. **リターゲット** `retarget.py`：BVH→関節角。オイラー角の2解のうち前フレームに近い解を選ぶ連続化、手首・前腕のマーカー乱れの速度制限、脚長比による根元移動の縮尺、接地高さの補正。体格差による根元相対の関節位置差は1〜6 cm。
3. **モーションライブラリ** `motion_library.py`：Custom-T2M-Labの全4,926クリップを変換し、4,604クリップ（50 Hzで151万フレーム、約8.4時間）が利用可能。学習4,148／評価456（ラベルごとに10%を固定で保留）。椅子が必要な863クリップは第1版から除外（椅子を置く第2版で追加）。
4. **GPU学習環境** `mjx_tracking.py`・`train_tracker.py`：参照状態からの開始、PHC型の追従報酬（体節位置・回転・速度）、平均体節誤差0.5 m超で失敗終了、クリップ終端は失敗ではなく打ち切りとして扱う専用ラッパー。
5. **独立評価** `evaluate_tracker.py`：学習済み方策をCPU版MuJoCoで、保留クリップの最初から最後まで実行。

学習結果は5章に追記します。

## 5. 学習結果

### 5.1 最初の試行で見つかった問題と対処

| 試行 | 症状 | 原因 | 対処 |
| --- | --- | --- | --- |
| v1（4億ステップ） | 評価エピソード長が59→約30ステップに悪化、KLが772→224万 | 方策を上限なしの正規分布にし、環境側で±1に切り詰めていたため、範囲外で勾配がなく平均出力が漂流（最大5,383） | 平均をソフトサイン関数で±1内に制限（`mean_clip_scale=1`） |
| v2（3,000万） | 学習中の報酬が負、エピソードが短くなる | 探索ノイズで関節が震え、学習中の消費電力が1ステップ約4万W。電力ペナルティが追従報酬を上回り、早く倒れるほど得になっていた | 電力・行動変化ペナルティを0にし、報酬を常に非負に |
| v3・v4（3,000万） | 指定した探索ノイズ0.15が効かず実際は0.69 | braxのtanh付き正規分布は`init_noise_std`を無視する | 平均有界の正規分布＋対数標準偏差0.15に変更 |
| v5（3,000万） | — | — | 評価エピソード長60→89、失敗率77%→52%と改善を確認 |

あわせて、参照データを関節角だけに縮小し体節姿勢はJAX内の順運動学で計算（GPUメモリ2.2 GB→0.4 GB）、順運動学を木の深さ単位で一括計算（CPU評価のコンパイル10分超→0.8秒）しました。いずれも保存済み参照との一致（誤差5e-7 m以下）を確認しています。

参考：残差ゼロ（参照をPDで追うだけ）では、静止立位の参照でも1〜2秒で前方へ倒れます。足首のPD剛性（400 Nm/rad）が倒立振子として支えるのに必要な値（約600）を下回ることが一因で、脚のゲインを大幅に上げても受動的には立てません。バランスは方策が能動的に学ぶ必要があります。

### 5.3 T2M生成動作そのものの問題（物理側とは別）

稼働中のT2M（`t2m-gpt-v2-20260823-best`、実時間API）で、データセットの立位ラベル文を中心に40動作を生成して調べました。生成依頼のみで、サービスの設定・モデルは変更していません。

| サンプリング設定 | 結果 |
| --- | --- |
| サービス既定（温度1.0、top_k無制限、cfg 2.0） | 40件中38件で、腰の高さが途中で0.75 m未満へ落ちる区間がある（中央値でフレームの19%）。体全体は一貫したしゃがみ姿勢で、BVH変換の不具合ではなく生成内容の混入。「立っている状態から、歩く。」の前進は0.07 m、「前向きに歩く」でも0.34 m。根元の最大速度は中央値8.2 m/s（モーキャプは0.47 m/s） |
| 温度0.7、top_k 20 | しゃがみの混入は消えるが、40件中39件がほぼ静止（関節の平均角速度0.1 rad/s未満）、全件が最大長7.7秒で打ち切り |

既定では崩れが混ざり、温度を下げると動かなくなるため、物理追従の成否以前にT2M出力の品質がG2のボトルネックになります。物理追従器を「実行可能性の判定器」として使い、T2Mの候補を複数生成して物理的に実行できたものを採用する方法は、日本語T2Mと物理制御をつなぐ研究上の論点にもなり得ます。

### 5.11 G6:段階 3 の家(四つの部屋+廊下+扉)を部屋から部屋へ回り、最後に寝室の椅子に座る(2026-10-16 21:35〜22:05)

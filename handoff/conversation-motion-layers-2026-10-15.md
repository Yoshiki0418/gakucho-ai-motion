# 会話画面の動作生成: 層構成方式(現行方式と切り替えて比較)

2026-10-15 追加。会話画面(`/`)の動作生成を、画面上で次の 3 モードから切り替えられるようにした。
既定は「現行」で、切り替えない限り従来と同じ動きになる。

| モード | 中身 |
| --- | --- |
| 現行 (`current`) | 行動タグごとに T2M-GPT で生成(従来どおり) |
| 新方式 (`layered`) | 意味の層(事前作成クリップ)+ リズムの層(SentiAvatar・研究評価用)+ 待機の層 |
| 新方式・リズムなし (`layered-semantic`) | 意味の層 + 待機の層(リズムの層の効果を切り分ける比較用) |

会話ヘッダーの「設定」→「動作生成」で切り替える(選択はブラウザに保存)。`/?motion_mode=layered` のように URL でも指定できる。
同じパネルに、届いた動作の内訳(どのタグを、収録クリップか T2M 事前生成か、土台が待機かリズムか、
SentiAvatar の生成時間)が出る。

## 仕組み

```
LLM 応答(本文に [act:タグ] を置く。語彙は現行と同じ 29 種)
  │ 文ごとに TTS → 発話の長さが確定
  ▼
バックエンドで 1 発話 = 1 本の BVH に合成(conversation_motion パッケージ)
  ③ 待機の層   立ち姿 + 呼吸・わずかな揺れ(会話の通し時刻で位相が連続)
  ② リズムの層 SentiAvatar(発話音声 → 全身の身振り)を学長の骨格へ移したもの
  ① 意味の層   タグの動作。動いた部位だけ、山場(ストローク)を語に合わせて重ねる
  │
  ├ 版 0: ①+③ を音声より先に送る(遅延なし)
  └ 版 1: ①+② を SentiAvatar が終わり次第送り、同じ発話の版 0 と差し替える
  ▼
フロントエンド: 発話の開始時刻で切り替え。遅れて届いた版は音声の現在位置から再生し、
             切り替え時は直前の見た目から 0.25 秒でつなぐ。
```

- **意味の層** — `backend/app/assets/conversation_motion/`。コミュニケーション動作カタログ(MOT_7xx)の
  モーキャプ 65 本(Custom-T2M-Lab `0010/01`、被験者 005)を、動作区間の切り出し・1 フレームだけ跳ぶ収録ノイズの補修・
  ストローク時刻と動く部位の判定をして持つ。収録の無い 2 タグ(`raise_hand` `wait`)は T2M で各 10 候補を作り、
  崩れ検出(しゃがみ込み・移動・反対側の腕)で 1 本を選んだ。`右手を上げる` は 10 候補すべてが左手か両手を上げており、
  鏡映した候補を採用している(本番の motion_handedness と同じ問題)。
  作り直し: `PYTHONPATH=backend/app/agent/general_conversation/tools python -m conversation_motion.build_library --output backend/app/assets/conversation_motion --canonical <T2M 出力の BVH>`
- **立ち姿の約束事(19:40 修正)** — 当初は被験者 005 の立ち姿(各収録の 1 フレーム目の平均)を基準にしたが、
  会話画面の待機姿勢・T2M の出力と比べて上腕と前腕が逆向きに 40〜60 度ねじれ、手首も約 40 度外へ折れており、
  GLB 上で「腕の向きがおかしい」状態だった(ユーザー指摘)。立ち姿を BvhViewer の待機姿勢(T ポーズ+部位ごとの固定角)に置き換え、
  収録は「被験者自身の立ち姿からのワールド回転の差分」としてその上に載せ直した(`neutral.py`)。指は収録の形のまま。
  リズムの層も同じ立ち姿の上に足すので、まとめて直る。
- **不具合の修正(20:10、ユーザー指摘「腕がありえない方向を向く」「対話のたびに浮いて沈む」)**
  - リズムの層の腕: SuSu の平均姿勢(手を体の前)からの回転差分を、腕を下ろした学長に足していたため、
    手を下ろす動きで学長の腕が背中側へ回っていた(手が胸より最大 20cm 後ろ)。腕は**骨の向きを合わせる**方式に変更
    (上腕・前腕・手の向きを SuSu に合わせ、ねじれは学長の立ち姿のまま)。最大 2cm に。
  - 頭: 関節ごとの上限が首 2・頭 1 で足し合わさり、短い発話であごが 16 度上がったままになっていた。
    胸のずれ(合計 8 度)と胸に対する頭のずれ(合計 8 度、上向き 4 度)で抑える。うなずきの戻りの上向き(17 度)も 5 度までに。
  - 手首: 手のひらを返す動作(どうぞ・わからない等)で、収録の前腕の回内・回外が手首に 90 度乗っていた。6 割を前腕へ移した(最大 37 度)。
  - 体をひねって指す動作: 鎖骨をワールド向きで置く補正をやめ、収録者の胴の向きの変化(8 割)を背骨に分けて足す方式に。
    指差しは正面を向き、反対の腕が背中側へ回らない。
  - 浮き沈み: 動作の 1 フレーム目の腰の高さを、会話画面は「立っているときの腰」とみなす。層構成の BVH は腰が
    T2M の約束事より 11cm 低く、待機に戻るたびに 11cm 浮いていた。T2M と同じ接地(最下関節 0.057)に合わせ、
    動作中と待機の腰の高さが一致することをブラウザで確認(0.890 / 0.890)。
    なお、ページを開いて最初の動作の前だけ腰が 11cm 高いのは現行方式でも同じ既存の挙動(既定の T ポーズ BVH 由来)。
- **重ね方** — 腕は動作の姿勢そのものへ、首・頭・背骨は動作の変化分を足す(うなずきの上でリズムの揺れが残る)。
  腰・脚はお辞儀だけ動かす(収録は 80 度近い最敬礼なので 4 割の深さ)。収録者が体をひねって指している動作でも、
  腕の向きは世界基準(クリップ先頭の腰の向き=正面)で保つ。
- **一貫性** — 同じ動作を 8 秒以内に繰り返さない(指差し↔どうぞ、考える↔こめかみ の代替、うなずきは浅くする)。
  同じ腕の動作が 1.1 秒以内に重なる場合は後を落とす。発話の終わりではみ出す動作は次の発話へ持ち越し、
  次の発話は前の発話の最終姿勢からつなぐ。ストロークは語の頭の 0.12 秒後に置く。
- **待機・傾聴の層** — 送信直後に浅いうなずき(受け取りの合図)を出す。応答の音声より先に動く。
- **生成の自由文**(`generate_motion` ツール・ユーザーの直接指示) — カタログに当たるものはクリップで出す
  (「左手を〜」は右手の収録を鏡映)。座る・立つなどクリップに無いものは現行の T2M 経路で生成する。
- **座っている間** は層構成に未対応のため、そのターンは現行方式で動かす(パネルに理由が出る)。

## リズムの層: SentiAvatar(研究評価専用)

SentiPulse Non-Commercial Source License v1.0。学内の研究評価として使い、本番運用はしない。
重み・出力はリポジトリに入れない(`.runtime/sentiavatar/` に置く)。

- 常駐サーバ `tools/sentiavatar/server.py`。公式の single_case_infer を 1 プロセスに常駐させ、
  プランナ(Qwen2-0.5B)は vLLM の代わりに transformers + 静的 KV キャッシュ + torch.compile(37 → 90 tok/s)。
- ホストのファイアウォール(ufw の既定 DROP)はコンテナ→ホストの通信を通さないため、
  **コンテナとして学長バックエンドと同じ Docker ネットワークに置く**:
  `tools/sentiavatar/run-container.sh gakucho-ai-motion_default gakucho-motion-sentiavatar`(GPU 0、別名 `sentiavatar:8110`)。
- 生成時間(起動時に暖機済み): 3 秒の発話で 1.0〜1.3 秒、11.5 秒の発話で約 4 秒。動作は音声長と一致。
- 骨格の移し方: SuSu の姿勢そのものではなく「SuSu の平均的な話し姿勢からのずれ」(骨盤の向きを固定した
  ワールド回転の差分)を、学長の立ち姿に足す。骨盤と脚は動かさない(足が滑らない)。背骨 0.6・首頭 0.7 倍に弱める。
  平均姿勢は `assets/conversation_motion/sentiavatar_reference.json`(日本語 TTS 5 文から算出)。
- 同じ音声には同じ動作が出る(プランナの温度 0.2・top_p 0.2 でほぼ決定的)。

## 確認したこと(2026-10-15)

- 単体テスト 13 件(`backend/tests/test_conversation_motion.py`)。既存の動作系テストも検証用コピーで通過。
- 本物の `text_chat_router` を LLM / TTS / DB だけ差し替えて本番イメージで実行(本番 DB・ネットワークには接続しない。
  `.runtime/staging/harness/router_harness.py`)。SSE の順序: 各発話で「動作(版 0)→ 音声」、
  SentiAvatar の版 1 は 1 発話目で音声の 1.4 秒後、2 発話目以降は再生前に届く。
- その記録をモックで再生し(`replay_server.py`)、ブラウザ(Chrome headless、約 40fps、`browser_check.mjs`)で再生ログを確認:

| | 動作の開始遅れ |
| --- | --- |
| 新方式 | 受け取りのうなずき 0.03 秒、各発話 0.01〜0.03 秒。版 1 は再生中に現在位置(1.3〜1.4 秒)から差し替え |
| 現行(T2M 生成 1.5 秒を模擬) | 0.4〜0.7 秒。前の動作の終了待ちで 6.1 秒遅れる動作あり |

- SSE 応答に `Cache-Control: no-transform` と `X-Accel-Buffering: no` を付けた。圧縮するプロキシ(開発用の
  Next.js)を通すと、後から届く版が圧縮バッファに溜まり数秒遅れていたため。本番の nginx は元々 `proxy_buffering off`。

## 未対応・次の課題

- 座位での層構成(上半身だけ重ねる)。
- タグの語彙は現行の 29 種のまま(比較を公平にするため LLM へのプロンプトは両モード共通)。
  収録は 65 本あるので、語彙の拡張と「使う場面」の説明の追加は次の段階。
- 1 発話目はリズムの層が途中から入る(版 0 → 版 1 の差し替え)。
- SentiAvatar は女性キャラクター SuSu のデータで学習されており、身振りの癖が学長に合うかは主観評価が要る。
- 実機での比較(無動作率・発話とのずれ・最初の動作までの時間・意味の適切さ)を `docs/sync-baseline` の手順で 3 モード分取る。

## 反映とロールバック

**本番に反映済み(2026-10-15 19:21〜19:24、ユーザー承認後)。** SentiAvatar コンテナ `gakucho-motion-sentiavatar` を
本番ネットワークで起動 → `backend/app` へ 4 点を反映してバックエンドを再起動(約 30 秒) → フロントエンドを再ビルドして入れ替え、
nginx を再読み込み。T2M・DB は再起動していない。反映後の確認(本番の nginx 経由、履歴は専用セッションで作って削除):

- 新方式: 受け取りのうなずき 0.4 秒(応答本文の生成中に出る)、各発話の動作が音声より先に届き、リズムの層の版は
  1 発話目で音声開始の 3.8 秒後(10.8 秒の発話の途中で差し替え)、2 発話目は再生前に到着
- 現行: 従来どおり T2M の生成結果が音声開始の 3.6 秒後に届く(2.3 秒の発話は既に終わっている = 改善前の課題そのもの)
- 座位を指定すると「座っている間は現行方式で動かします」で現行方式に戻る

反映の手順: `.runtime/staging/backend-app` の変更 4 点(`conversation_motion/`、`assets/conversation_motion/`、
`motion_tool.py`、`routers/text_chat_router.py`)を `backend/app` へ移してバックエンドを再起動、
SentiAvatar コンテナを本番ネットワークで起動、フロントエンド(`app/page.tsx`、`useTextChat.ts`、`BvhViewer/index.tsx`)を再ビルド。
ロールバック: `.runtime/staging/backend-app-original/` と `.runtime/staging/frontend-original/` から戻して再起動・再ビルドし、
`docker rm -f gakucho-motion-sentiavatar`。
